# Master Delivery Checklist

This is the phase-level view. Check an item only when all linked tickets are `Done` with evidence.

## Phase 0 — Decisions and validation

- [ ] Product brief, ICP, service model, and success metrics approved.
- [ ] Founder and matchmaker workflow research completed.
- [ ] Applicant/client concept and consent testing completed.
- [ ] Nocturne direction, cross-platform token contract, and content principles approved.
- [ ] Architecture ADRs required for foundation approved.
- [ ] Threat model and data-flow review approved.
- [ ] Privacy/legal requirements and partner terms identified.
- [ ] Provider/API feasibility matrix completed.
- [ ] Match-science evidence review, construct register, outcome taxonomy, and prospective pilot approved.
- [ ] Optional conversational-intake concept, consent boundary, and speech feasibility approved.
- [ ] Private-beta scope and go/no-go gates approved.

## Phase 1 — Foundation

- [ ] Monorepo and generated contract workflow established.
- [ ] Cross-platform design tokens, generated platform outputs, and foundational components established.
- [ ] Docker local environment is reproducible.
- [ ] CI, branch protection, scans, and release checks established.
- [ ] Staging and production deployment foundations established.
- [ ] Authentication, RBAC, partner scopes, and audit foundation complete.
- [ ] Private media pipeline and malware scanning complete.
- [ ] Observability, redaction, backups, restore, and runbooks established.

## Phase 2 — Intake and campaigns

- [ ] Campaign configuration and controlled branding complete.
- [ ] Public campaign landing and eligibility complete.
- [ ] Application, save/resume, uploads, and consent complete.
- [ ] Optional conversational/hybrid intake and field-by-field approval complete if the research gate passes.
- [ ] Invite codes, referrals, quotas, and waitlist complete.
- [ ] Applicant review and lifecycle transitions complete.
- [ ] Interview, verification, status, and notification workflows complete.
- [ ] Privacy request and withdrawal workflows complete.
- [ ] Limited partner reporting and access complete.

## Phase 3 — Matchmaking operations

- [ ] Client/candidate profiles and provenance complete.
- [ ] Criteria, search, and duplicate resolution complete.
- [ ] Shortlists and human recommendation review complete.
- [ ] Mutual introduction approval complete.
- [ ] Feedback, follow-up, outcome, and safety workflows complete.
- [ ] Support and administrative recovery tools complete.

## Phase 4 — AI assistance

- [ ] AI policies and provider controls approved.
- [ ] Structured summary and completeness assistance complete.
- [ ] Evidence-backed retrieval/recommendations complete.
- [ ] Evaluation, red-team, versioning, monitoring, and cost controls complete.
- [ ] Human overrides and audit evidence complete.

## Phase 5 — Flutter

- [ ] Flutter architecture and generated client established.
- [ ] Secure authentication/session handling complete.
- [ ] Accepted-member profile/privacy workflows complete.
- [ ] Introduction decision and feedback workflows complete.
- [ ] Push notification privacy and preferences complete.
- [ ] Safety/support paths complete.
- [ ] App Store and Play privacy/release requirements complete.

## Phase 6 — Private beta

- [ ] Accessibility verification complete.
- [ ] Performance and campaign load testing complete.
- [ ] Independent security audit and remediation complete.
- [ ] Privacy/legal launch review complete.
- [ ] Restore and incident exercises complete.
- [ ] Synthetic rehearsal and consenting beta complete.
- [ ] Montecito/Santa Barbara campaign go/no-go approved.
- [ ] Launch monitoring and retrospective complete.
